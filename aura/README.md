# Aura - AWS Optimizer Orchestrator

Aura is a job scheduling and execution system for AWS optimization workloads. It orchestrates the execution of build and solve phases for optimization jobs using Docker containers and provides comprehensive monitoring and logging.

## Features

- **Job Orchestration**: Manages lifecycle of optimization jobs (build → solve)
- **Parallel Execution**: Configurable limits for concurrent build and solve jobs
- **Plugin System**: Pluggable heuristics for job scheduling (FIFO included)
- **Docker Integration**: Runs optimization tasks in isolated containers
- **Monitoring**: CPU and memory usage tracking
- **Event Storage**: JSONL-based event logging for analysis
- **Configuration**: YAML-based configuration with environment variable overrides

## Installation

Install with `uv` (recommended):

```bash
# Install in development mode
uv pip install -e .

# Or install from source
uv pip install .
```

## Configuration

Configure Aura using the `configs/config.yaml` file. Key settings:

```yaml
# Docker image for optimizer
optimizer_image: "registry-git.lsd.ufcg.edu.br/pedro.serey/awsome-savings:or-tools"

# Concurrency limits
default_max_build: 2
default_max_solve: 1

# Directories
runs_dir: "./orchestrator_runs"
monitor_log_dir: "./monitor_logs"

# Docker mounts
families_mount: "/optimizer-files"
proto_mount: "/optimizer-proto"
logs_mount: "/optimizer-logs"
```

### Environment Variable Overrides

You can override any configuration using environment variables with the `AURA_` prefix:

```bash
export AURA_OPTIMIZER_IMAGE="my-custom-image:latest"
export AURA_DEFAULT_MAX_BUILD=4
export AURA_LOG_LEVEL="DEBUG"
```

## Usage

### Command Line

After installation, run Aura with:

```bash
# Basic usage
aura --demand-root /path/to/family/directories

# Advanced usage
aura --demand-root /path/to/families \
     --plugin fifo \
     --max-build 3 \
     --max-solve 2 \
     --poll-interval 0.5 \
     --config /path/to/custom/config.yaml
```

### Python Module

```bash
# Run as module
python -m aura --demand-root /path/to/families
```

### Programmatic Usage

```python
from aura.config import get_config
from aura.plugins import load_plugin
from aura.core.scheduler import Scheduler

# Load configuration
config = get_config()

# Load heuristic plugin
plugin = load_plugin("fifo")

# Create and run scheduler
scheduler = Scheduler(
    demand_root="/path/to/families",
    plugin=plugin,
    max_build=config.default_max_build,
    max_solve=config.default_max_solve
)

# Discover and run jobs
jobs = scheduler.discover_jobs()
scheduler.run()
```

## Architecture

### Core Components

- **Job**: Represents a family optimization job with state management
- **Scheduler**: Orchestrates job discovery, selection, and execution
- **Runner**: Executes Docker containers for build/solve phases  
- **Monitor**: Extracts CPU/memory metrics from job logs
- **Store**: Records job events in JSONL format

### Plugin System

Aura supports pluggable heuristics for job selection:

- **FIFO**: First-in-first-out scheduling (included)
- **Custom**: Implement `HeuristicPluginProtocol` for custom logic

Example custom plugin:

```python
from aura.plugins import HeuristicPluginProtocol

class MyHeuristic:
    def name(self) -> str:
        return "my_heuristic"
    
    def select(self, candidates, running, capacity_total, cap_build, cap_solve):
        # Your selection logic here
        return selected_jobs[:capacity_total]
```

## Docker Requirements

Aura requires Docker to execute optimization containers. The optimizer image should:

1. Include `/optimizer/run_build.sh` and `/optimizer/run_solve.sh` scripts
2. Accept volume mounts for input files and output logs
3. Generate standard output files (result_cost.csv, etc.)

## Monitoring & Logging

### Event Logs

Job events are stored in `{runs_dir}/{job_id}.jsonl`:

```json
{"ts": "2025-01-10T14:30:00", "job_id": "abc-123", "family": "family1", "phase": "build", "kind": "started", "state_at_write": "BUILDING", "meta": {...}}
{"ts": "2025-01-10T14:30:45", "job_id": "abc-123", "family": "family1", "phase": "build", "kind": "finished", "state_at_write": "BUILT", "meta": {"ok": true, "duration_sec": 45.2}}
```

### Metrics

CPU and memory metrics are extracted from job-generated CSV files and included in event metadata.
